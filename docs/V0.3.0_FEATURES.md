### 2. Multi-Thumb Slider Segments

Each segment renders as a dual-thumb slider on its tag-specific track row.

#### Interaction Model

1. **Add Segment:** Click `[+Scene]`, `[+Camera]`, etc. buttons
2. **Resize:** Drag left/right thumbs to adjust start/end frames
3. **Reposition:** Drag the center area to move the entire segment
4. **Edit:** Double-click to open the segment modal
5. **Delete:** Click the × button on the segment chip

#### Frame Grid Rules (CRITICAL)

⚠️ **Two different rules apply:**

| Element | Rule | Valid Values | Example |
|---------|------|--------------|---------|
| **Pipe length** (totalFrames) | 8n+1 | 41, 49, 57, ..., 241, 441 | 121 = 8×15 + 1 |
| **Segment positions** (start/end) | Multiple of 8 | 0, 8, 16, 24... | 120 = 8×15 |
| **Keyframe positions** | Multiple of 8 | 0, 8, 16, 24... | 64 = 8×8 |

**Common mistake:** The 8n+1 rule applies ONLY to total pipe length. Segment and keyframe positions use multiples of 8.

**Error message clarification:** When you see "must be a multiple of 8", it refers to the **POSITION on the timeline** (a frame number like 0, 8, 16), NOT the image content.

- All positions snap to multiples of 8 (0, 8, 16, 24...)
- Minimum span: 8 frames (one inference batch)
- Boundaries: `frameStart % 8 === 0`, `frameEnd % 8 === 0`
- Validation runs on every change; invalid changes show toast errors

### 3. Keyframe System

Max 3 keyframes per pipe, positioned on the timeline.

#### Keyframe Types

| Type | Requires | Use Case |
|------|----------|----------|
| `url` | imageSrc | Image-to-video reference |
| `txt2img` | prompt | Text-generated reference |
| `img2img` | referenceUrl + prompt | Style transfer reference |

#### Behavior

- Wide chips (~72px) with left edge at frame position
- Drag to reposition (snaps to 8-grid)
- Click to edit properties
- Warning border when required fields missing (e.g., img2img without referenceUrl)

### 5. Pipe Management

Multiple independent pipelines per session.

#### Operations

- **Add Pipe:** Click `[+ Add Pipe]` button
- **Reorder:** ↑/↓ buttons to move pipes
- **Duplicate:** Creates exact copy with new ID
- **Delete:** Remove pipe (minimum 1 required)
- **Configure:** Length, FPS, Quality, Creativity settings

#### Pipe Settings

| Setting | Range | Default | Description |
|---------|-------|---------|-------------|
| Length (frames) | 41–441 | 121 | Total duration (8n+1 rule) |
| FPS | 18, 24, 30, 48, 60 | 24 | Frame rate |
| Resolution | 480p, 720p, 1080p | 720p | Output resolution |
| Quality (Q) | 5–30 | 18 | CFG scale for generation |
| Creativity (C) | 0.5–15 | 7 | Temperature for generation |

### 6. Prompt Compiler

Converts visual timeline configuration into structured prompt text.

#### Output Formats

- `json`: `{tag: value}` structure

- `xml`: `<tag>value</tag>` structure

### 7. Frame Math System

Pure utility functions ensuring all frame values obey the 8n+1 rule.

#### Key Functions

| Function | Purpose |
|----------|---------|
| `snapTo8(n)` | Round down to nearest multiple of 8 |
| `snapTo8nPlus1(n)` | Round up to nearest 8n+1 value |
| `clampLength(len, max)` | Clamp pipe length to valid range |
| `validateSegments(segs, maxEnd)` | Check boundaries, overlaps, min span |
| `validateKeyframe(kf)` | Check slot range, source requirements |
| `frameToX(frame, totalFrames)` | Convert frame to percentage for rendering |
| `xToFrame(x, totalFrames)` | Convert percentage back to frame |

---

### 8. Data Persistence

All composer data stored in SQLite with localStorage fallback.

#### Database Schema

- `projects` table — project metadata
- `sessions` table — session configs (fps, resolution, etc.)
- `pipes` table — individual pipe configurations
- `pipe_keyframes` table — keyframe positions and sources
- `pipe_prompt_nodes` table — global nodes and segment prompts
- `session_settings` table — app-level settings per session

#### Sync Behavior

- Backend-first: Always attempts SQLite write
- Fallback: Persists to localStorage on failure
- Unsynced indicator: Badge shown when data only in localStorage

## Design Rules (Non-Negotiable)

### R1 — Two-Layer Segment Hierarchy

1. **Global Layer:** Root-level nodes per pipe (`tag: 'global_style'`)
2. **Segment Layer:** Per-tag track rows for all other tags

### R2 — Single Frame Number Space

All UI elements share coordinate system `(0..pipe.lengthFrames)`. One drag updates position everywhere via single store action.

### R3 — Keyframe Wide Chips

Keyframes render as ~72px wide chips with left edge at frame position. Repositioning snaps to grid. Max 3 slots per pipe.
